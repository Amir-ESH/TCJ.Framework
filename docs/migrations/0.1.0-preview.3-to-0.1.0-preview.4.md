# Migrate from 0.1.0-preview.3 to 0.1.0-preview.4

This guide tracks the supported upgrade from **0.1.0-preview.3** to the current **0.1.0-preview.4** development line for all five TCJ Framework packages.

## Upgrade the package set

`0.1.0-preview.3` is the latest published preview. `0.1.0-preview.4` is currently under development and must not be treated as a published NuGet.org release until its release workflow completes.

When `0.1.0-preview.4` is published, keep all referenced TCJ packages on the same version.

## Source compatibility

No source changes are required for consumers whose convention-registered dependencies are already effectively public. Affected applications that previously relied on a nested `public` dependency inside a non-public containing type being discovered must either make the full containing-type chain public after API review or register that dependency explicitly with `IServiceCollection`.

## Changed dependencies

No production package dependency changes are currently recorded for `0.1.0-preview.4`.

## Changed defaults

No runtime default changes are currently recorded for `0.1.0-preview.4`.

## Configuration

No application configuration changes are currently required.

## Dependency injection

Convention scanning now follows effective CLR visibility. A convention-marked top-level dependency must be `public`, and a nested dependency is eligible only when the dependency and every containing type are `public`. `TCJ0003` reports marked concrete types that do not meet this rule.

If a nested dependency intentionally belongs inside a non-public container, keep the container non-public, remove the misleading convention marker, and register the service explicitly with normal `IServiceCollection` APIs. Do not widen a containing type solely to silence the analyzer without reviewing the public API impact.

## Middleware

No ASP.NET Core middleware ordering or registration changes are currently required.

## Entity Framework Core

No Entity Framework Core consumer migration is currently required.

## SQL Server

No SQL Server consumer migration is currently required.

## Transactional outbox

The **transactional outbox is opt-in**. Existing applications that do not call `AddTcjOutbox` remain outbox-disabled.

Consumers that enable the outbox continue to own the `TCJ_OutboxMessages` schema through a **consumer-controlled migration**. TCJ does not create or migrate that table automatically. Persisted **event type names are compatibility contracts**; keep stable event names when upgrading or provide an explicit application migration strategy for previously persisted messages.

No outbox schema, event-name, or processing-default change is currently recorded for `0.1.0-preview.4`.

## Behavior

Convention assembly scanning no longer treats a nested `public` type inside a non-public containing type as scan-eligible. This aligns runtime registration with effective accessibility and the new `TCJ0003` analyzer. Effectively public dependencies continue to register as before.

## Rollback

During development, public consumers should remain on the published `0.1.0-preview.3` packages. After `0.1.0-preview.4` is eventually published, any version-specific rollback requirements must be documented here before release readiness.

## Known limitations

This document tracks only the explicitly validated `0.1.0-preview.3` to `0.1.0-preview.4` upgrade path. It does not imply compatibility with arbitrary future previews or untested platform/provider combinations. EF Core and SQL Server Native AOT support remains experimental under the existing TCJ Native AOT policy.
