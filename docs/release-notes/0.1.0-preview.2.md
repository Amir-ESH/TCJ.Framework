# TCJ Framework 0.1.0-preview.2

Release date: **2026-08-14**

`0.1.0-preview.2` is the second public preview of TCJ Framework. This release turns the initial framework foundation into a much more strongly verified distribution, with packaged Native AOT evidence, broader integration and reliability features, cross-platform consumer validation, reproducible packages, SBOM/provenance controls, and significantly stronger release gates.

## Highlights

### Packaged Native AOT support

Native AOT support is now an executable release contract rather than a project-build claim.

- `TCJ.Core` has full packaged Native AOT evidence.
- `TCJ.DependencyInjection` is supported through the explicit reflection-free registration path; convention-based assembly scanning remains a documented non-AOT path.
- `TCJ.AspNetCore` is validated through the supported Minimal API path.
- The release pipeline publishes and executes a `linux-x64` Native AOT application that consumes the locally packed release-candidate NuGet packages.
- Candidate package versions are verified both at restore time and from the assemblies loaded by the native process.
- Unexpected `IL2xxx` or `IL3xxx` trim/AOT diagnostics fail the gate; TCJ does not use a warning-count baseline to normalize new warnings.
- `TCJ.EntityFrameworkCore` and `TCJ.EntityFrameworkCore.SqlServer` remain explicitly Experimental for Native AOT because the upstream EF Core Native AOT boundary still requires separate treatment.

### Reliability and production integration

This preview adds several opt-in and production-oriented capabilities:

- transactional SQL Server outbox processing with same-transaction persistence, lease-based claiming, retry/dead-letter behavior, replay, and cleanup;
- bounded retry, cooperative timeout, circuit-breaker, domain-event retry, and SQL Server execution-strategy primitives;
- liveness/readiness health checks, SQL Server connectivity and migration readiness, safe ASP.NET Core health endpoints, and health telemetry;
- backend-neutral tracing and metrics based on standard .NET diagnostics/OpenTelemetry-compatible primitives;
- stronger concurrency and thread-safety stress coverage with deterministic seeds and replayable failure traces.

### Release-blocking compatibility fixes

The final release candidate also includes the compatibility fixes validated immediately before release preparation:

- Testcontainers-based test projects explicitly pin `SSH.NET` `2026.0.0`, the patched line for the upstream security issue, with `PrivateAssets=all` so this test dependency is not exposed by TCJ runtime packages.
- Convention-based dependency registration and health-check activation now carry the trimming metadata required by the Native AOT analyzers while preserving the documented reflection-free supported path.
- EF Core soft-delete query-filter composition uses the EF Core 10 query-filter metadata APIs, preserves existing anonymous and named filters, and no longer relies on the obsolete `GetQueryFilter()` API.
- The SQL Server same-`DbContext` concurrency stress scenario now uses a deterministic command gate instead of timing delays, removing scheduler-dependent test behavior.

### Release and supply-chain guarantees

The release process now verifies the artifacts consumers actually install:

- SDK package validation against the immutable `0.1.0-preview.1` published API baseline;
- clean-room package consumers across Linux, Windows, and macOS;
- automated package-upgrade validation from `0.1.0-preview.1` to `0.1.0-preview.2`;
- reproducible primary and symbol package builds;
- portable PDB, Source Link, XML documentation, NuGet metadata, and package-content verification;
- CycloneDX JSON SBOM generation with direct/transitive dependency relationships, licenses, hashes, repository identity, and source commit;
- SHA-256 checksum manifests and GitHub build-provenance attestations;
- SQL Server Testcontainers integration tests and cross-platform ASP.NET Core end-to-end tests;
- mutation testing, performance benchmarks, architecture tests, property-based testing, fuzzing, documentation validation, and release-blocking policy verification.

### Licensing, branding, and project governance

The current development/release line is licensed under **GNU LGPL v3.0 only (`LGPL-3.0-only`)**. Copies of `0.1.0-preview.1` that were distributed under MIT retain the permissions granted with those copies.

TCJ also now separates software licensing from project identity through the TCJ Trademark and Brand Policy, and defines official upstream authority through the Contributor License Agreement, governance policy, and CODEOWNERS configuration. Independent forks may continue to evolve and be commercialized subject to the applicable LGPL terms, while official TCJ project identity and upstream release/governance authority remain separate.

This release contains the same five public package identities:

- `TCJ.DependencyInjection`

- `TCJ.AspNetCore`

Keep all TCJ packages used by an application on the same release version.

## Installation

```bash
dotnet add package TCJ.Core --version 0.1.0-preview.2
dotnet add package TCJ.DependencyInjection --version 0.1.0-preview.2
dotnet add package TCJ.EntityFrameworkCore --version 0.1.0-preview.2
dotnet add package TCJ.EntityFrameworkCore.SqlServer --version 0.1.0-preview.2
dotnet add package TCJ.AspNetCore --version 0.1.0-preview.2
```

Install only the modules required by the application. Provider and integration packages bring their required TCJ dependencies transitively.

## Upgrade from 0.1.0-preview.1

The validated upgrade path from `0.1.0-preview.1` to `0.1.0-preview.2` requires **no consumer source-code changes**. The version-specific breaking-change manifest contains no approved source-breaking entries, and clean-room upgrade consumers are required to restore, build, and run against both versions from the same source tree.

Notable upgrade details:

- upgrade all referenced TCJ packages together to avoid version skew;
- `TCJ.DependencyInjection` now brings health-check-related transitive dependencies used by the new health-check integration;
- transactional outbox support is opt-in and does not alter an existing EF Core model unless the application explicitly registers/maps it;
- enabling the outbox requires a consumer-controlled migration for `TCJ_OutboxMessages` and its indexes;
- existing convention-based DI scanning remains available, but Native AOT consumers should use the documented reflection-free registration path.

See [Migrate from 0.1.0-preview.1 to 0.1.0-preview.2](../migrations/0.1.0-preview.1-to-0.1.0-preview.2.md) for complete migration and rollback guidance.

## Preview notice

TCJ Framework is still pre-`1.0.0`. Preview releases may contain deliberately approved public API changes. Pin the exact preview version, review the changelog and migration guide before upgrading, and avoid mixing TCJ package versions in the same application.

## Release validation

The official release is published only from the exact `main` commit that passes release preflight. The release pipeline verifies build/test/coverage policies, integration suites, package consumers, upgrade compatibility, reproducibility, documentation, SBOM/checksums, packaged Native AOT execution, and the final package set before NuGet publication.

The immutable release tag is:

```text
v0.1.0-preview.2
```

See [Release automation](../releasing.md) and the repository `RELEASE_CHECKLIST.md` for the complete publication contract.
