# 0.1.0-preview.4 development release notes

`0.1.0-preview.4` is the active development line and is not a published NuGet.org release until the release workflow completes.

## Strong Types

- Adds `TCJ.Generators` as analyzer-only compile-time tooling for generated Strongly Typed IDs and primitive-backed Value Objects.
- Strong IDs support `Guid`, `int`, and `long`; Value Objects support `string`, `Guid`, `int`, `long`, and `decimal` with application-owned normalization and validation.
- Generated parsing and formatting are culture-stable, JSON uses scalar wire shapes, and generated EF conversion expressions keep domain declarations free of EF Core dependencies.
- Explicit `TCJ.EntityFrameworkCore` registries persist generated Strong IDs and Value Objects through primitive provider columns without runtime assembly scanning.

## Release contract

The candidate package set is now blocked when Strong Types fail in packaged consumption. Release verification restores a clean consumer from local `.nupkg` files for `TCJ.Core`, `TCJ.Generators`, `TCJ.EntityFrameworkCore`, and `TCJ.AspNetCore`, then exercises generated construction, validation, JSON, Minimal API parsing, and EF conversion behavior.

Generated source is compared byte-for-byte across clean rebuilds. Incremental-generator tests verify unrelated syntax changes reuse unchanged Strong ID and Value Object model stages, and a many-type fixture enforces a coarse median rebuild performance budget suitable for CI rather than microsecond-level timing.

The Native AOT packed consumer now uses generated Strong IDs and Value Objects with source-generated System.Text.Json metadata and Minimal API parsing. `TCJ.Generators.dll` is required only as an analyzer asset and release verification fails if that implementation assembly appears in Native AOT publish output.

## Compatibility and migration

Generated public APIs are compatibility surfaces just like handwritten APIs. Scalar JSON shapes and primitive persistence shapes are also versioned contracts. Applications adopting Strong Types should keep TCJ package versions aligned and review the [0.1.0-preview.3 to 0.1.0-preview.4 migration guide](../migrations/0.1.0-preview.3-to-0.1.0-preview.4.md) before changing validation, JSON, or persisted backing values.

EF Core and SQL Server Native AOT support remains experimental; the Strong Types Native AOT guarantee is intentionally non-EF.
