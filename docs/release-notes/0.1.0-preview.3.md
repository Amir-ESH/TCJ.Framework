# TCJ Framework 0.1.0-preview.3

Release date: **2026-08-16**

`0.1.0-preview.3` is the third public preview of TCJ Framework. This release is intentionally narrow: it keeps the five-package runtime/API surface from `0.1.0-preview.2` unchanged and hardens how published NuGet packages are presented and revalidated after publication.

## Highlights

### Package-specific NuGet READMEs

Each TCJ package now ships a dedicated NuGet README sourced from `docs/nuget/` rather than embedding the GitHub repository README.

- `TCJ.Core`, `TCJ.DependencyInjection`, `TCJ.EntityFrameworkCore`, `TCJ.EntityFrameworkCore.SqlServer`, and `TCJ.AspNetCore` each have package-specific Markdown content.
- NuGet README sources are kept outside production source projects under `docs/nuget/`.
- Raw repository HTML and repository-relative Markdown assets are rejected by release validation for `0.1.0-preview.3` and newer versions.
- The pack mapping emits every package-specific source as package-root `README.md`, matching NuGet's `PackageReadmeFile` contract.
- Regression validation rejects the previously broken `PackagePath="/"` plus `Link="README.md"` mapping that could produce `NU5039`.

### Published-package restore isolation

Published-package consumers are now restored independently from the repository's local release-candidate feed.

- `smoke/NuGet.Config` remains dedicated to local candidate-package validation such as packaged Native AOT checks.
- `smoke/NuGet.Published.Config` is explicitly NuGet.org-only for published-package smoke and dependency-audit restores.
- The published feature smoke restores explicitly with the published configuration and then runs with `--no-restore`, preventing an implicit restore from inheriting the local candidate feed.
- The scheduled published-package dependency audit uses the same source isolation.

### Published transactional-outbox smoke reliability

The Linux post-publication outbox smoke now uses the same convention-based handler registration path as TCJ consumers without registering the same handler twice.

- The duplicate explicit `SmokeChangedHandler` registration was removed.
- An early guard requires exactly one `SmokeChanged` handler registration so a future registration regression fails with a direct diagnostic.
- The verified `0.1.0-preview.2` post-publication run successfully persisted, claimed, dispatched, and marked the outbox message processed; liveness/readiness and package-only consumer checks also completed successfully across the supported platforms.

### Stronger release verification

Release validation now treats NuGet README presentation as part of the artifact contract.

- all five package README source files must exist and identify their package;
- README content must be Markdown-only under the repository policy and use supported absolute links or in-document anchors;
- the README pack mapping must target the exact declared package path;
- the packed `README.md` bytes must match the corresponding repository source;
- published-package smoke remains enabled for the immutable published baseline and the current release target.

## Packages

This release contains the same five public package identities:

- `TCJ.Core`
- `TCJ.DependencyInjection`
- `TCJ.EntityFrameworkCore`
- `TCJ.EntityFrameworkCore.SqlServer`
- `TCJ.AspNetCore`

Keep all TCJ packages used by an application on the same release version.

## Installation

After `0.1.0-preview.3` is published to NuGet.org:

```bash
dotnet add package TCJ.Core --version 0.1.0-preview.3
dotnet add package TCJ.DependencyInjection --version 0.1.0-preview.3
dotnet add package TCJ.EntityFrameworkCore --version 0.1.0-preview.3
dotnet add package TCJ.EntityFrameworkCore.SqlServer --version 0.1.0-preview.3
dotnet add package TCJ.AspNetCore --version 0.1.0-preview.3
```

Install only the modules required by the application. Provider and integration packages bring their required TCJ dependencies transitively.

## Upgrade from 0.1.0-preview.2

The validated upgrade path from `0.1.0-preview.2` to `0.1.0-preview.3` requires **no consumer source-code changes**. `eng/breaking-changes.json` contains no approved breaking entries for this version pair.

Notable upgrade details:

- upgrade all referenced TCJ packages together to avoid version skew;
- there is no production package dependency change in this release;
- no runtime default, application configuration, EF Core model, SQL Server schema, or public API change is introduced by the release-infrastructure fixes;
- applications that do not enable the transactional outbox remain outbox-disabled;
- existing Native AOT support boundaries remain unchanged.

See [Migrate from 0.1.0-preview.2 to 0.1.0-preview.3](../migrations/0.1.0-preview.2-to-0.1.0-preview.3.md) for complete migration and rollback guidance.

## Preview notice

TCJ Framework is still pre-`1.0.0`. Preview releases may contain deliberately approved public API changes. Pin the exact preview version, review the changelog and migration guide before upgrading, and avoid mixing TCJ package versions in the same application.

## Release validation

The official release is published only from the exact `main` commit that passes release preflight. The release pipeline verifies build/test/coverage policies, integration suites, package consumers, upgrade compatibility, reproducibility, documentation, SBOM/checksums, package-specific README contents, packaged Native AOT execution, and the final package set before NuGet publication.

The immutable release tag is:

```text
v0.1.0-preview.3
```

Do not move the tag or publish different package bytes under the same version.
