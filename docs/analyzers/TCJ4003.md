# TCJ4003: Generic Strong ID declarations are unsupported

| Property | Value |
| --- | --- |
| ID | `TCJ4003` |
| Category | `TCJ.StrongTypes` |
| Default severity | `Error` |
| Code fix | Unavailable |
| Introduced in | Unshipped |

## Cause

A declaration marked with `StronglyTypedId<T>` declares one or more type parameters.

## Rule description

The Strong ID generator emits a closed API for one concrete identifier type. Generic Strong ID declarations are outside that contract and are diagnosed instead of being silently skipped.

## How to fix

Remove the Strong ID declaration's type parameters and create concrete Strong ID types for the required identities.

## Examples

### Code with diagnostic

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId<T>; // TCJ4003
```

### Corrected code

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId;
```

## Suppression

Suppression does not cause the generator to emit a generic Strong ID implementation. Prefer a concrete identifier declaration.

## Known limitations

TCJ does not infer or specialize generic Strong ID declarations for closed consumer type arguments.

## Compatibility notes

`TCJ4003` is a default `Error` and turns the previous unsupported generic case into an intentional compiler diagnostic without changing valid generated APIs.
