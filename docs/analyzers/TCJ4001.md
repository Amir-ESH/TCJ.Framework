# TCJ4001: Strong ID declaration has an unsupported shape

| Property | Value |
| --- | --- |
| ID | `TCJ4001` |
| Category | `TCJ.StrongTypes` |
| Default severity | `Error` |
| Code fix | Unavailable |
| Introduced in | Unshipped |

## Cause

A declaration marked with `StronglyTypedId<T>` is not a supported top-level `public` or `internal` `readonly record struct`.

## Rule description

TCJ Strong IDs use one deterministic declaration policy: top-level, `public` or `internal`, `readonly`, `record struct`, and partial. `TCJ4001` covers unsupported shape details other than the dedicated non-partial (`TCJ4000`) and generic (`TCJ4003`) contracts.

## How to fix

Change the declaration to a top-level `public` or `internal readonly partial record struct`. Moving a nested type or changing class/struct semantics can affect consumer code, so TCJ does not offer an automatic code fix.

## Examples

### Code with diagnostic

```csharp
[StronglyTypedId<Guid>]
public partial record struct OrderId; // TCJ4001: not readonly
```

### Corrected code

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId;
```

## Suppression

Suppress only when the declaration is intentionally not intended to generate a TCJ Strong ID. Generation remains disabled for the invalid declaration even when the diagnostic is suppressed.

## Known limitations

The generator does not generate nested Strong IDs or alternative class/plain-struct shapes. Those shapes are diagnosed rather than partially supported.

## Compatibility notes

`TCJ4001` is a default `Error`. The rule formalizes the declaration policy already required by the generator and prevents downstream generated-code errors.
