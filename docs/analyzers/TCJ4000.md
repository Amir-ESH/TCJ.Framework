# TCJ4000: Strong ID declaration must be partial

| Property | Value |
| --- | --- |
| ID | `TCJ4000` |
| Category | `TCJ.StrongTypes` |
| Default severity | `Error` |
| Code fix | Unavailable |
| Introduced in | Unshipped |

## Cause

A declaration marked with `StronglyTypedId<T>` is not declared `partial`.

## Rule description

The Strong ID generator adds the supported identifier API in another declaration of the same type. The attributed declaration must therefore be partial. TCJ reports this contract directly and does not emit partial generated output for the invalid type.

## How to fix

Add the `partial` modifier and keep the declaration compatible with the required `readonly partial record struct` shape.

## Examples

### Code with diagnostic

```csharp
[StronglyTypedId<Guid>]
public readonly record struct OrderId; // TCJ4000
```

### Corrected code

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId;
```

## Suppression

Suppression is not recommended because the generator intentionally emits no source for the invalid declaration. Suppressing the diagnostic does not make generation succeed.

## Known limitations

This rule validates the declaration that carries the Strong ID attribute. Other declaration-shape requirements are reported separately by `TCJ4001`.

## Compatibility notes

`TCJ4000` is a default `Error` because a non-partial declaration cannot receive the generated API. Valid unrelated Strong IDs continue to generate.
