# TCJ4004: Strong ID member conflicts with generated API

| Property | Value |
| --- | --- |
| ID | `TCJ4004` |
| Category | `TCJ.StrongTypes` |
| Default severity | `Error` |
| Code fix | Unavailable |
| Introduced in | Unshipped |

## Cause

A user-defined member on a valid Strong ID declaration conflicts by name or signature with API that TCJ must generate.

## Rule description

TCJ checks the generated constructor, `Value`, `IsDefault`, parsing and formatting signatures, explicit backing conversions, Guid creation helpers, `StrongIdConversion`, and `StrongIdJsonConverter`. Diagnostics are reported at the exact conflicting user member. Unrelated overloads are allowed.

## How to fix

Remove or rename the conflicting member, or change an overload so its signature no longer collides with the generated contract. TCJ does not overwrite user members and does not guess which user behavior may be deleted safely.

## Examples

### Code with diagnostic

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId
{
    public Guid Value { get; } // TCJ4004
}
```

### Corrected code

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId;
```

A non-conflicting overload remains valid:

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId
{
    public static OrderId Parse(int value) => default;
}
```

## Suppression

Suppression is not recommended. The generator intentionally emits no source for a declaration with a generated-member collision, so suppressing the error leaves the Strong ID API incomplete.

## Known limitations

The rule protects the API emitted by the current generator version. New generated API introduced in a future compatible release must receive equivalent collision protection before shipping.

## Compatibility notes

`TCJ4004` is a default `Error`. It replaces confusing downstream duplicate-member/operator errors with a TCJ-owned diagnostic while preserving non-conflicting user overloads.
