# TCJ4005: Strong type attributes are ambiguous

| Property | Value |
| --- | --- |
| ID | `TCJ4005` |
| Category | `TCJ.StrongTypes` |
| Default severity | `Error` |
| Code fix | Unavailable |
| Introduced in | Unshipped |

## Cause

A declaration has duplicate `StronglyTypedId<T>` attributes or combines a Strong ID attribute with `ValueObject<T>`, leaving the intended strong-type generation contract ambiguous.

## Rule description

A declaration must select exactly one TCJ strong-type contract. TCJ reports each conflicting attribute location and does not generate partial Strong ID output for an ambiguous declaration.

## How to fix

Keep exactly one `StronglyTypedId<T>` attribute for a Strong ID declaration and remove conflicting TCJ strong-type attributes. Choose the backing type deliberately when duplicate Strong ID attributes disagree.

## Examples

### Code with diagnostic

```csharp
[StronglyTypedId<Guid>]
[ValueObject<Guid>]
public readonly partial record struct OrderId; // TCJ4005 on both attributes
```

### Corrected code

```csharp
[StronglyTypedId<Guid>]
public readonly partial record struct OrderId;
```

## Suppression

Suppression does not resolve which generation contract should win, and generation remains disabled for the ambiguous declaration. Remove the ambiguity instead.

## Known limitations

The rule covers TCJ strong-type attributes known to the current generator. It does not arbitrate unrelated third-party attributes.

## Compatibility notes

`TCJ4005` is a default `Error`. Attribute locations are reported deterministically, and unrelated valid Strong IDs continue to generate.
