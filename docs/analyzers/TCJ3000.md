# TCJ3000: Reflection-based dependency scanning is not compatible with Native AOT or trimming

| Property | Value |
| --- | --- |
| ID | `TCJ3000` |
| Category | `TCJ.AotTrimming` |
| Default severity | `Warning` |
| Code fix | Optional |
| Introduced in | Unshipped |

## Cause

This diagnostic is reported when reflection-based TCJ dependency injection scanning is used in a project that enables Native AOT or trimming.

Runtime assembly scanning depends on reflection metadata that may not be available after trimming or in Native AOT deployments.

## Rule description

The analyzer checks TCJ dependency injection registration usage in projects configured with Native AOT or trimming enabled.

It reports reflection-based dependency scanning patterns that may prevent deterministic startup behavior in AOT-compatible applications.

Normal JIT applications without trimming or Native AOT enabled are not affected.

## How to fix

Use AOT-safe explicit dependency registration instead of runtime reflection scanning.

The code fix only offers transformations where the analyzer can prove that the change preserves behavior.

## Examples

### Code with diagnostic

```csharp
services.AddTcjDependencyInjection();
```

### Corrected code

```csharp
services.AddTcjDependencyInjection(options =>
{
    // Register dependencies explicitly.
});
```

## Suppression

Suppress this warning only when reflection scanning is intentionally preserved and the application has been validated for its deployment model.

## Known limitations

The analyzer intentionally avoids changing non-empty reflection scanning configurations because automatically replacing registrations could change application behavior.

## Compatibility notes

This diagnostic only provides compile-time guidance. It does not change runtime behavior for existing applications.
