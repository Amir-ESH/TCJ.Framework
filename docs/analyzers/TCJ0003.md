# TCJ0003: Convention dependency must be effectively public

| Property | Value |
| --- | --- |
| ID | `TCJ0003` |
| Category | `TCJ.DependencyInjection` |
| Default severity | `Error` |
| Code fix | Optional; available only when changing the marked type itself is sufficient |
| Introduced in | Unshipped |

## Cause

A concrete class implements one of TCJ's six convention-registration lifetime markers, but the class is not effectively public.

TCJ convention scanning only considers effectively public concrete types. For a top-level type, the type itself must be `public`. For a nested type, the nested type and every containing type must be `public`. A `public` nested class inside an `internal`, `private`, `protected`, or otherwise non-public containing type is therefore not an eligible convention dependency.

Abstract marked base classes are intentionally excluded because the convention scanner does not register abstract implementations.

## Rule description

TCJ0003 resolves the six TCJ lifetime markers by metadata identity and reports a concrete source class when all of the following are true:

- the class implements, directly or through inheritance, `ITransientDependency`, `IScopedDependency`, `ISingletonDependency`, `ISelfTransientDependency`, `ISelfScopedDependency`, or `ISelfSingletonDependency`;
- the class is not abstract;
- the class is not compiler-generated;
- the class is not a domain-event handler handled by TCJ's separate domain-event registration path; and
- either the class itself or one of its containing types is not `public`.

The diagnostic is reported on the marked type declaration. When a nested type is declared `public` but a containing type blocks effective accessibility, the diagnostic identifies that containing type explicitly.

## How to fix

Make the marked concrete type effectively public when it is intended to participate in TCJ convention scanning.

The automatic **Make type public** fix is offered only when changing the reported type's own accessibility is sufficient and syntactically safe. It preserves the type's base class, service interfaces, TCJ lifetime marker, and other modifiers.

No automatic fix is offered when a containing type is the accessibility blocker. Making a containing type public could expose unrelated members or alter a larger public API surface, so that decision requires explicit developer review. The fixer is also conservative for file-local types and multi-declaration partial types where a single local edit is not sufficient.

## Examples

### Code with diagnostic

```csharp
using TCJ.DependencyInjection.Lifetimes;

public interface IOrderService;

internal sealed class OrderService : IOrderService, IScopedDependency;
```

`OrderService` produces TCJ0003 because the convention marker declares registration intent but the concrete implementation is not public.

A containing type can also be the blocker:

```csharp
using TCJ.DependencyInjection.Lifetimes;

internal static class Services
{
    public sealed class CacheWarmer : ISelfSingletonDependency;
}
```

`CacheWarmer` is declared `public`, but it is not effectively public because `Services` is `internal`. TCJ0003 identifies `Services` as the containing-type blocker and does not offer an automatic fix.

### Corrected code

```csharp
using TCJ.DependencyInjection.Lifetimes;

public interface IOrderService;

public sealed class OrderService : IOrderService, IScopedDependency;
```

For a nested dependency, all containing types must also be public:

```csharp
using TCJ.DependencyInjection.Lifetimes;

public static class Services
{
    public sealed class CacheWarmer : ISelfSingletonDependency;
}
```

If the implementation is intentionally internal, remove the convention marker and register it explicitly through normal `IServiceCollection` APIs instead of widening accessibility only to satisfy convention scanning.

## Suppression

Suppress TCJ0003 only when the marked type is intentionally excluded from TCJ convention scanning and the team accepts that the marker will not provide convention registration for that type. Prefer a narrowly scoped `.editorconfig`, local pragma, or `SuppressMessage` rather than disabling TCJ diagnostics globally.

If an internal implementation is registered explicitly, removing the unused TCJ lifetime marker is usually clearer than suppressing the diagnostic because it avoids communicating convention-registration intent that the scanner cannot honor.

## Known limitations

TCJ0003 analyzes source accessibility and marker identity; it does not determine whether the containing assembly is actually passed to a convention-scanning overload at runtime.

The automatic fix is intentionally conservative. It does not make containing types public, does not edit service interfaces, does not rewrite file-local declarations, and does not attempt a multi-document accessibility rewrite for partial types.

The rule excludes domain-event handlers because TCJ processes those through a dedicated registration path and their diagnostics are governed separately.

## Compatibility notes

TCJ0003 is a default `Error` because a convention-marked concrete dependency that is not effectively public cannot satisfy TCJ's public-type convention-registration contract.

The runtime scanner's accessibility filter uses effective CLR visibility, so a nested type is scan-eligible only when both it and every containing type are public. Existing TCJ0001 and TCJ0002 analysis is aligned with the same effective-public boundary to avoid cascading diagnostics for types the scanner will not inspect.

The code fix changes only the marked type's accessibility when that local transformation is sufficient. It never changes service interfaces or automatically exposes a containing type.
