# TCJ4002: Strong ID backing type is unsupported

| Property | Value |
| --- | --- |
| ID | `TCJ4002` |
| Category | `TCJ.StrongTypes` |
| Default severity | `Error` |
| Code fix | Unavailable |
| Introduced in | Unshipped |

## Cause

`StronglyTypedId<T>` uses a backing type other than `Guid`, `int`, or `long`.

## Rule description

The generated parsing, formatting, conversion, persistence-expression, and JSON contracts are defined only for the three supported backing types. Unsupported types are rejected intentionally instead of being ignored silently.

## How to fix

Use `Guid`, `int`, or `long` as the Strong ID backing type. If another value type is required, model it outside the current Strong ID generator contract.

## Examples

### Code with diagnostic

```csharp
[StronglyTypedId<decimal>]
public readonly partial record struct MoneyId; // TCJ4002
```

### Corrected code

```csharp
[StronglyTypedId<long>]
public readonly partial record struct OrderId;
```

## Suppression

Suppression does not enable unsupported generation and is therefore not a substitute for choosing a supported backing type.

## Known limitations

Custom numeric types, enums, strings, and arbitrary unmanaged types are not supported by the current Strong ID contract.

## Compatibility notes

`TCJ4002` is a default `Error`. Supported `Guid`, `int`, and `long` generated APIs and wire semantics are unchanged.
